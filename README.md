# BLADE — Barber Booking

Вебзастосунок онлайн-запису до демонстраційного барбершопу. Український інтерфейс, чотири послуги, три майстри, живий розклад і кабінет адміністратора.

## Можливості

- Запис у чотири кроки: послуга → майстер → дата й час → контакти.
- Серверна перевірка доступності з урахуванням тривалості, робочих днів і київського часу.
- Захист від подвійного бронювання: транзакція SQLite та унікальні 15-хвилинні інтервали.
- Перенесення без втрати попереднього часу при помилці, скасування та повторний запис.
- Завантаження події у форматі ICS для особистого календаря.
- Кабінет: денний календар трьох майстрів, список із фільтром статусів, завершення візитів і статистика.
- Зміна цін, тривалості послуг, робочих годин та днів. Початкові ціна й тривалість попередніх записів зберігаються.
- Два режими: ізольована публічна демонстрація та спільна студія з паролем адміністратора.
- Постійна база SQLite, Docker, перевірка здоров’я та автоматичний перезапуск.

## Межі демонстрації

Барбершоп, майстри та послуги вигадані. За замовчуванням `DEMO_MODE=true`: кожен відвідувач має власну студію, прив’язану до підписаного cookie. У демо користувач може спробувати і роль клієнта, і кабінет. Це навмисний доступ лише до власної пісочниці, а не авторизація справжнього адміністратора.

Використовуйте тестові контакти. Тестові записи старші семи днів видаляються щогодинним завданням. Cookie також діє сім днів. Втрата cookie означає втрату доступу до власної демо-студії. SMS, email, оплати та автоматичні нагадування не підключені. Фото — зовнішній декоративний ресурс Unsplash; основні функції працюють без нього.

## Запуск

Потрібен Node.js 24 або новіший. Зовнішніх npm-залежностей немає.

```powershell
npm start
```

Відкрийте `http://127.0.0.1:3000`. База створюється у `data/studio.sqlite`.

```powershell
npm run check
npm test
```

Налаштування передаються через змінні середовища; `.env` читає Docker Compose, а локальний Node автоматично його не завантажує. Для локального запуску можна використати `node --env-file=.env server.mjs` після заповнення файлу.

## Docker

Скопіюйте `.env.example` у `.env` та встановіть випадковий `SESSION_SECRET` щонайменше з 32 байтів. Файл `.env` не потрапляє до Git або образу.

```sh
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8090/api/health
```

Контейнер слухає лише `127.0.0.1:8090` на хості. Публічний HTTPS забезпечує окремий зворотний проксі. Дані зберігаються у Docker volume `studio-data`. Не використовуйте `docker compose down -v`, якщо потрібно зберегти записи.

## Режим реальної студії

Встановіть `DEMO_MODE=false`, унікальний `SESSION_SECRET` та `ADMIN_PASSWORD` довжиною від 16 символів і перезапустіть контейнер. Кабінет вимагатиме пароль; клієнт бачить і змінює лише власні записи. Вільні інтервали спільні для всіх клієнтів. Після входу адміністратора загальний список доступний у кабінеті. Режим реальної студії використовує окремий простір `live`; демонстраційні записи до нього не переносяться.

Цей режим — базова реалізація для однієї студії. Перед комерційним запуском потрібно визначити політику зберігання контактів і резервного копіювання, додати відновлення клієнтського доступу, індивідуальні акаунти працівників та потрібні канали повідомлень.

## Структура

```text
server.mjs             HTTP API, сесії, SQLite, транзакції
lib/studio.mjs         Послуги, майстри, час і доступність
public/                Інтерфейс без етапу збірки
tests/studio.test.mjs   Інтеграційні та предметні перевірки
compose.yaml           Розгортання з постійною базою
deploy/                Скрипт розгортання на VPS
docs/                  Перевірки та опис кейсу
```

## Перевірено

`npm test` перевіряє перетини інтервалів, паралельне бронювання, ізоляцію демо-відвідувачів, права клієнта й адміністратора, перенесення, скасування, збереження ціни та даних після перезапуску. Фактичний стан розгортання та ручної перевірки: [docs/VERIFICATION.md](docs/VERIFICATION.md).
